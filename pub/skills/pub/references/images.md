# 이미지·아이콘 규칙 (고정 규칙 1의 상세)

> 이 파일의 "규칙 N", "N번"은 `pub` 스킬 `SKILL.md`의 번호를 가리킨다.

`pub` 스킬 [고정 규칙] 1번의 전체 내용이다. 프레임에 이미지·아이콘·SVG가 있으면 이 파일을 읽고 그대로 따른다.

1. **이미지/아이콘**:
   - **SVG(벡터)**: 실제 이미지 파일로 만들지 않고 `<svg>...</svg>`를 HTML 안에 인라인으로 삽입한다. `fill="currentColor"`로 색상을 CSS에서 제어할 수 있게 한다. 이건 규칙 7(인라인 스타일 금지) 대상이 아니다. **이 규칙은 페이지 안에 아이콘이 몇 개 있는지와 무관하게, 아이콘 하나하나에 개별적으로 적용된다.** 화살표, 플러스 버튼, 체크 아이콘처럼 단순한 개별 아이콘은 페이지 전체에 그런 아이콘이 수십 개 있어도 전부 다 인라인 SVG로 만든다 — "개수가 많으니 이번엔 이미지로 처리하자"고 판단하지 않는다.
   - **아이콘을 임의로 지어내지 않는다(필수)**: 피그마 참고 코드에서 아이콘/그래픽 요소가 `<svg>`+`<path>` 형태가 아니라 `<img src={...}>`(에셋 URL)로 내려오면, 그건 피그마가 그 요소를 이미지 에셋으로 제공한 것이다. "이런 모양이겠지"라고 비슷해 보이는 아이콘을 직접 지어내서 대체하지 않는다. 실제 에셋을 다운로드해서 확인한다.
   - **다운로드한 에셋이 SVG 파일이면, `<img src="...svg">`로 참조하지 않고 그 파일 내용을 열어서 인라인으로 옮긴다(필수, 실제 사고 사례 있음).** "아이콘을 임의로 지어내지 않는다"는 규칙과 "SVG는 항상 인라인"이라는 규칙이 부딪히는 지점이다 — 다운로드한 게 SVG(텍스트/XML)라면 그 내용을 읽어서 `<svg>...</svg>`로 그대로 인라인 삽입하고, 다운로드했던 파일 자체는 최종 결과물에 남기지 않는다. `<img>` + 파일 저장 방식은 **진짜 래스터 이미지(PNG/JPG)일 때만** 쓴다. "실제 에셋을 확인해야 한다"는 게 "파일로 남겨서 img로 참조해도 된다"는 뜻이 아니다.
   - **이전에 다른 페이지에서 썼던 아이콘 path를 재사용하지 않는다(필수).** "이거 예전에 만든 아이콘이랑 비슷해 보이니까 그 path 그대로 쓰면 되겠지"처럼, 지금 조회하지 않고 과거 다른 프레임에서 쓴 SVG path를 기억해서 재활용하지 않는다 — 다른 프레임이면 겉보기에 비슷해도 실제 디자인이 다를 수 있다. 아이콘마다 이번에 조회한 이번 프레임의 실제 데이터에서 나온 path만 쓴다.
   - **반복 SVG의 `id` 충돌 방지(필수)**: `<defs>`의 `linearGradient`/`mask`/`clipPath`/`filter` id가 같은 페이지에서 여러 번 반복되면 두 번째부터 깨진다. 인스턴스마다 id를 고유하게(`-1`, `-2` 등) 만든다.
   - **래스터 이미지**: 추출 가능하면 `files/{영역}/images/common/파일명`으로 저장. 불가능하면 임의로 만들지 않고 크기만 잡은 빈 영역(전용 클래스로 크기 정의)으로 처리.
   - SVG인지 래스터인지 애매하면 임의로 정하지 말고 물어본다.
   - **크롭 정확도**: 부모 프레임/여백까지 통째로 잘라내지 않고, 실제 이미지 경계와 일치하는 가장 안쪽 노드만 추출한다.
   - **크롭 검증 및 재크롭**: 다운로드 파일의 실제 픽셀 크기와 피그마 레이아웃 표시 크기를 비교, 다르면 ImageMagick/Pillow 등으로 재크롭. 좌표 판단이 애매하면 전/후 비교 이미지로 확인받는다.
   - **크기 보정**: `<img>`에 `object-fit: cover; object-position: center;` 기본 적용.
   - **`<img>` 태그에 `width`/`height` 속성을 넣지 않는다(필수).** 크기는 CSS에서 클래스로 지정한다 — HTML 속성으로 박아두면 반응형에서 크기가 바뀌어야 할 때 CSS 값과 속성값이 서로 다르게 남아 혼란스럽고, 실제로 CSS가 이겨서 속성값은 의미 없어지는데도 코드에 남아있어 가독성만 떨어뜨린다. 이미지 크기는 전부 CSS(`width`, `height`, 또는 `aspect-ratio`)로 관리한다.
   - **img/svg 크기를 여러 개를 묶는 공통(범용) 선택자로 한 번에 지정하지 않는다(필수).** `img { width: 100px; }`나 `svg { width: 24px; height: 24px; }`처럼 태그 자체를 범용으로 선택해서 페이지 안의 서로 다른 여러 이미지/아이콘에 한꺼번에 같은 크기를 적용하지 않는다 — 이러면 그 중 하나만 반응형에서 다르게 조정하고 싶어도 공통 규칙을 건드리면 나머지 전부가 같이 바뀌어버려서 개별 수정이 불가능해진다. **이미지/아이콘 인스턴스마다 각자의 전용 클래스**(`.main-hero__badge`, `.notice-panel__day-dot` 등)를 만들어서 그 클래스에 크기를 지정한다. 여러 이미지가 우연히 같은 크기를 공유하더라도, 각자 나중에 독립적으로 조정될 가능성이 있으면 전용 클래스로 분리해둔다.
   - **확장자-내용 일치 검증(필수)**: 저장 시 `file` 명령어 등으로 확장자와 실제 포맷이 맞는지 확인, 불일치 시 바로잡는다.
