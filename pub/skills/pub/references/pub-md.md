# PUB.md 형식과 운용 규칙

`pub` 스킬 2번에서 `PUB.md`를 **만들거나 갱신할 때만** 읽는다. 이미 있는 파일을 읽기만 할 때는 필요 없다.

   `PUB.md` 형식 — 없는 항목은 비워두지 말고 `미정`이라고 적는다.
   ```markdown
   # PUB.md — 이 프로젝트의 퍼블리싱 설정 (pub 스킬이 읽고, 사람도 고친다)

   - CSS 구조: 통합형 (inc/{영역}/css/) | 분산형
   - 영역: web1, web2, bcnimda
   - 콘텐츠 컨테이너: .inner / 1200px / 좌우 20px
   - 폰트: inc/lab/css/font.css 의 @font-face — Pretendard 400·500·700
   - head 기준 파일: html/web1/main.html
   - 공용 라이브러리 경로: inc/lab/js/
   - 브레이크포인트: 태블릿 1295px, 모바일 744px

   ## 이 프로젝트에서 쓰는 컴포넌트
   - 카드 목록: .notice-card (변형: --point) — html/web1/notice.html
   - 탭: .sub-tab + .is-active

   ## 이 프로젝트에서 내린 판단
   - 배너 장식 SVG는 통 이미지로 (2026-08-27, 슬라이드 전환 예정이라)

   ## 반복해서 고쳐야 했던 것
   - 서브 페이지 GNB는 메인과 색이 다름 — .gnb--sub 써야 함
   ```
   - **이 파일은 사람도 고칠 수 있는 프로젝트 자산이다.** 사용자가 적어둔 값이 있으면 그게 우선이고, 스킬이 임의로 덮어쓰지 않는다 — 실제와 다른 항목만 고친다.
   - 작업 중 새로 확정한 것(새 토큰, 새 컨테이너 클래스)이 생기면 그 항목을 갱신한다.
   - **`PUB.md`는 쌓이는 파일이다. 작업이 끝날 때마다 아래를 이어서 적는다(필수) — 이게 이 프로젝트의 다음 화면이 더 잘 나오게 만드는 유일한 장치다.**
     - **컴포넌트**: 이번에 새로 만든 재사용 가능한 클래스를 `이름 — 어디서 썼는지` 한 줄로. 다음 페이지가 같은 걸 새로 만들지 않게 한다.
     - **판단**: 규칙 12로 사용자에게 물어서 정한 것, 또는 애매해서 한쪽으로 정한 것을 `무엇을 어떻게, 왜` 한 줄로. 같은 상황이 또 오면 다시 묻지 않는다.
     - **반복 수정**: **사용자가 이번에 고쳐달라고 한 것 중 다음에도 반복될 만한 것**을 한 줄로. 같은 지적을 두 번 받지 않는 게 목표다.
     - 이번에 특별한 게 없었으면 아무것도 적지 않는다. 억지로 채우지 않는다.
     - **이 파일은 여러 퍼블리셔가 git으로 공유한다. 그래서 두 가지를 지킨다.**
       - **이미 적힌 항목과 반대되는 내용을 새 줄로 덧붙이지 않는다.** 그러면 다음 사람이 뭘 따라야 할지 모른다. 방침이 실제로 바뀐 거면 **기존 줄을 고치고** 괄호로 사유를 남긴다. 바뀐 게 맞는지 확신이 없으면 규칙 12로 물어본다.
       - **개인 취향은 적지 않는다.** "이 프로젝트는 원래 이렇다"만 적고, "이번엔 이렇게 하고 싶었다"는 적지 않는다. 판단 기준은 **다른 퍼블리셔가 다음 페이지를 만들 때도 그대로 따라야 하는가**이다.
   - **파일이 길어지지 않게 관리한다.** 한 항목은 한 줄, 이미 적힌 내용은 다시 적지 않는다. 비슷한 항목이 서너 개 쌓이면 하나로 묶어 요약한다. **전체 60줄을 넘으면 오래됐거나 이제 당연해진 항목부터 지운다** — 매 실행 읽히는 파일이라 길어지면 그 자체가 비용이다.
   - **`PUB.md`는 커밋해야만 공유된다(필수 안내).** `/pub`은 각자 컴퓨터에서 돌기 때문에, 이 파일을 고쳐놓고 커밋하지 않으면 그 경험은 그 사람 컴퓨터에만 남고 팀에는 아무것도 쌓이지 않는다. `design.css`와 같은 구조다.
     - 이 파일을 만들거나 고쳤으면 **완료 보고에 무엇을 추가했는지 적고, 결과물과 함께 커밋하라고 명시적으로 안내한다.** "알아서 하겠거니" 하고 넘어가지 않는다.
     - 작업 시작 시 이 파일이 최신인지는 알 수 없다. 내용이 실제 코드와 어긋나 보이면 `git pull`을 먼저 해보라고 안내한다.
