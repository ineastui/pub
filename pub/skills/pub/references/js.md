# JS 작성 규칙 (pub 스킬 5번의 상세)

> 이 파일의 "규칙 N", "N번"은 `pub` 스킬 `SKILL.md`의 번호를 가리킨다.

사용자가 JS를 요청했을 때만 읽는다.

아래 기준에 따라 `inc/{영역}/js/design.js`(공통) 또는 페이지 전용 파일로 나눠서 작성한다.

   - **탭 전환, 아코디언, 토글처럼 여러 페이지에서 반복될 만한 단순한 공통 UI 동작**은 `design.js`(영역당 하나) 하나에 모아서 작성한다. 이미 `design.js`가 있으면 이어서 추가, 없으면 새로 만든다.
   - **배너 슬라이드처럼 특정 페이지(주로 메인)에만 있고 무겁거나 복잡한 전용 기능**은 `design.js`에 같이 넣지 않고 별도 파일(예: `main.js`)로 분리한다 — 서브 페이지가 불필요한 코드를 로드/파싱하지 않게 하고, 어떤 페이지에 어떤 기능이 있는지 파일만 보고 알 수 있게 한다.
   - **JS 파일을 만들었으면 HTML에 링크까지 반드시 넣는다(필수).** `</body>` 직전에 `<script src="/inc/{영역}/js/design.js" defer></script>`를, 페이지 전용 파일도 만들었으면 그 줄을 이어서 넣는다(공통 → 페이지 전용 순서). 파일만 만들고 링크를 빠뜨리면 아무것도 동작하지 않는다.
   - 공용 라이브러리는 기존 프로젝트의 경로를 그대로 따른다(예: `inc/lab/js/`). 새 경로를 임의로 만들지 않는다.
   - **`design.js`는 그 영역의 여러 페이지(메인, 서브 등)가 공유하는 파일이므로, 특정 페이지에만 있는 요소를 다루는 코드는 그 요소가 없는 다른 페이지에서 에러 없이 조용히 넘어가야 한다(필수).** `querySelector`로 가져온 요소가 없으면(`null`) 그 블록을 건너뛰게 방어 코드를 넣는다(예: `const el = document.querySelector('.main-hero__play-btn'); if (el) { el.addEventListener(...); }`). `null`인 요소에 바로 메서드를 호출해서 에러가 나면, 그 아래에 이어지는 다른 페이지용 코드까지 같이 멈추기 때문이다. 여러 기능을 한 파일에 모을수록 이 방어 코드가 더 중요해진다.
